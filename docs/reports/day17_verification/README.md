## 1. 6 项改进（按用户反馈逐条对照）

| # | 用户反馈 | 改法 | 工作量 |
|---|---|---|---|
| 1 | 没有同理心，冷冰冰 | 同理心开头一句话（按 problem_type + category 选短句） | 5 分钟 |
| 2 | 正确的废话太多 | 删除"诊断结果""置信度""问题分析""准确度"标题，改"第一步/第二步/第三步"分步方案 | 5 分钟 |
| 3 | 信息重复 | root_causes 去重（前缀相同只保留 1 条）+ 模板内不重复表达 | 5 分钟 |
| 4 | 英文术语突兀 | reason_name 中文化（Merchandise/Services Not Received → 商品/服务未收到）；模板用大白话解释（13.1 → 买家说没收到货） | 5 分钟 |
| 5 | 没有主动提供下一步 | CTA 不再说"回复派单"，直接问"需要我帮你创建工单让 XX 团队跟进吗？" | 5 分钟 |
| 6 | "置信度 80%" 用户看不懂 | 删除百分比数字，改为"较低/中等/较高/很高"标签（仅低置信度场景显示） | 5 分钟 |

## 2. 模板体系设计

```python

    ("拒付", "not_received", "Visa"): Visa_13_1_模板,         # Visa 13.1
    ("拒付", "not_authorized", "Mastercard"): MC_4837_模板,    # MC 4837
    ("支付失败", "pix_weekend", None): BR_Pix_模板,             # BR Pix 延迟
    ("结算延迟", "pix_weekend", None): BR_Pix_模板,             # BR Pix 延迟 (备用)
    ("结算延迟", None, None): BR_Pix_模板,                     # BR Pix 延迟 (备用)

_PDA_DEFAULT_TEMPLATE: { problem_type 自替换的通用模板 }

```

```
---
未授权类拒付容易反复触发。

MC 4837 拒付（持卡人不认这笔交易），这样处理：

**第一步：检查 3DS 验证记录**
- 在 OP 商户后台 → 风控管理 → 3DS 配置
```

```
msgs: 1

BR Pix 周末凌晨延迟是巴西央行系统维护导致的常见问题。

BR Pix 周末凌晨延迟到账，这样处理：

**第一步：确认是否在维护窗口**
- 巴西央行 Pix 系统维护时间：周六、周日凌晨 2:00–6:00（巴西时间）

- 状态『已扣款』但买家未收到：买家侧银行问题
- 状态『处理中』：耐心等待或催收

**第三步：超 30 分钟未到账**
- 主动联系买家，请其查银行 App
- 回复『派单』我帮您创建工单让 BR 团队跟进
```

## 9. 已知边界

- **场景覆盖**：当前 3 个核心场景有专属模板（Visa 13.1 / MC 4837 / BR Pix），其他走默认模板。
  - 默认模板给"收集证据 / 自查配置 / 让团队协助"三步建议（兜底可用）
  - 后续可加更多场景模板（Amex 退款异常 / Webhook 回调失败 / 拒付 13.5 等）

- **BR Pix 模板适配**：BR Pix 走 `_br_pix_template()`，覆盖 3 个 key（"支付失败"/"结算延迟" × "pix_weekend"/None）。
  - 实际测试 "BR 站 Pix 周六凌晨怎么总是延迟不到账" 命中"结算延迟" → 走 BR Pix 模板 ✅

- **LLM 链路**：Mock 模式下 actions 是固定的；接 Qwen 后 actions 会根据 prompt 动态生成，模板的 steps 仍是骨架（不会被覆盖）。
